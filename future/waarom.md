# Code Literacy in het C#-curriculum — *waarom*
**De inhoudelijke en pedagogische aanleiding voor de nieuwe editie**

*Tim Dams • Lector C# & Cybersecurity • AP Hogeschool Antwerpen • mei 2025*

> Dit document beschrijft de aanleiding, probleemstelling en verantwoording voor de koers van de nieuwe editie van *Zie Scherp Scherper*. Voor de concrete uitwerking en het schrijfplan, zie [hoe.md](hoe.md).

---

## 1. Aanleiding

AI-ondersteund programmeren is geen toekomstige trend meer — het is de huidige werkelijkheid. Tools zoals GitHub Copilot, Cursor en Claude genereren vandaag al productiekwaliteits-code in seconden. Dit stelt ons voor een fundamentele curriculumvraag:

> **Wat moet een IT-student in 2025 kunnen als AI het schrijven van code overneemt? En hoe bereiden wij hen daar optimaal op voor?**

De nieuwe editie van *Zie Scherp Scherper* beantwoordt die vraag met een concrete, laagdrempelige aanpassing van het bestaande C#-curriculum — zonder de huidige opbouw te verlaten.

---

## 2. Probleemstelling

### Wat verandert er in de beroepspraktijk?

Developers van morgen zullen minder code schrijven, maar meer code lezen, beoordelen en verantwoorden. Zij zullen:

- AI-gegenereerde code moeten reviewen op correctheid en veiligheid
- Subtiele bugs herkennen die een AI niet zelf signaleert
- Architecturale keuzes in bestaande codebases begrijpen en verdedigen
- Verantwoordelijkheid dragen voor code die zij niet zelf schreven

### Wat verandert er niet?

Conceptueel begrip van programmeertaal blijft onmisbaar. Wie niet begrijpt wat een iterator, een null-reference of een geheugenleak is, kan AI-output niet beoordelen. De kennis verdwijnt niet — de manier waarop we ze toetsen moet mee-evolueren.

### Het bijkomende probleem: begrijpend lezen

Parallel aan de AI-evolutie stellen we vast dat begrijpend lezen bij studenten structureel achteruitgaat. Passieve consumptie van content heeft het actief-lineair lezen vervangen. Code lezen vereist net die actieve, trage aandacht. Dit maakt de uitdaging tweeledig: we moeten niet alleen de lesstof aanpassen, maar ook de leesvaardigheid zelf mee trainen.

---

## 3. Impact op het curriculum

De voorgestelde aanpak (zie [hoe.md](hoe.md)) verandert geen fundamenten:

| Wat blijft hetzelfde | Wat verbetert |
|---|---|
| Bestaande lesopbouw blijft volledig intact | Studenten zijn beter voorbereid op AI-ondersteund werk |
| Geen nieuwe vakken of ECTS-aanpassingen nodig | Toetsvorm meet dieper begrip |
| Handmatig schrijven blijft in jaar 1 als fundament | Rode draad doorheen de volledige bachelor mogelijk |
| Minimale bijscholing voor lectoren | Leesvaardigheid wordt expliciet getraind |

---

## 4. Besluit

Deze koers vraagt geen grote investering — geen nieuw vak, geen nieuwe ECTS, geen volledige herschrijving. Hij vraagt wel een bewuste keuze: we meten niet langer alleen of studenten code kunnen produceren, maar ook of ze code kunnen doorgronden.

Die verschuiving is niet optioneel. In een wereld waar AI code schrijft, is de developer die AI kan sturen, beoordelen en verantwoorden de developer die waarde toevoegt. Dat is de professional die wij willen afleveren.
